# tp108 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来；内容像是贴错了（整段说明文字当成脚本、行数比原文件多得离谱）也会当场提醒。扫描之前还能先过一道扫前检查，看看范围里有没有刚收录还没扫过的、上次扫描之后被改过的文件。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5108>

端口固定为 `5108`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除
2. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单。保存文件前会先过一遍成组校验：路径重复、后缀不在范围、内容为空这类硬问题直接拦下并标到输入项上；内容疑似贴错（整段说明文字当成脚本、行数比原文件多得离谱）只在表单里提醒，确认后仍可保存
3. 命中清单区顶部可以选定只看某一条规则、某一个文件或者某一个级别。点扫前检查（或点按规则扫一遍时会先自动检查一遍），页面上列出这一轮范围里刚收录还没扫过的、上次扫描之后被改过的两类文件清单与条数，并提示这一轮的命中会因此与上一轮不可比；扫描之后给出这一轮参与比对的规则条数、范围里的文件个数、一共命中多少条，并按级别、按规则、按文件分别汇总
4. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；如果指定了一条停用的规则，页面上会写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 收录校验口径

- 收录或修改文件时先过一遍成组校验，路径重复、后缀不在收录范围、内容为空这类硬问题会一次列全并拦下，与保存时的拦截口径一致
- 内容疑似贴错的只做提醒、不拦截：脚本与配置类文件（js、sh、yml）去掉注释与空行后，含中文句读标点的行占到一定比例，会提醒可能把整段说明当成脚本贴进来了（文档类文件本身就是写说明的，不查这一条）；修改已有文件时行数比原文件多出数倍的，会提醒可能把别的内容一起贴进来了
- 校验接口只读不改数据，同样的输入查多少次结论都一样

## 扫前检查口径

- 每扫完一轮，范围内的文件会记下扫描时刻与当时内容的指纹，作为"上一轮"的基准
- 扫前检查把本轮范围里的文件分成两类列出：还没留下扫描足迹的（刚收录还没扫过）、当前内容指纹与上次扫描时不同的（上次扫描之后被改过），并提示这一轮的命中会因此与上一轮不可比
- 内容指纹按文件内容计算，只改路径或备注不算被改过，改回去也不算被改过
- 扫前检查只读不改数据，也不取当前时间，同样的数据查多少次结论都一样

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。每个文件记录里还带着扫描足迹（上次扫它的时刻与当时内容的指纹），扫前检查以此为基准，旧数据没有这两个字段时按还没扫过处理。

## 接口一览

| 方法   | 路径              | 说明                                             |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | /api/health       | 服务状态检查                                     |
| GET    | /api/rules        | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索 |
| POST   | /api/rules        | 新建规则                                         |
| GET    | /api/rules/:id    | 查看单条规则                                     |
| PATCH  | /api/rules/:id    | 修改规则                                         |
| DELETE | /api/rules/:id    | 删除规则                                         |
| GET    | /api/files        | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files        | 收录文件                                         |
| POST   | /api/files/check  | 收录前的成组校验，返回硬问题与贴错提醒，不改数据 |
| GET    | /api/files/:id    | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id    | 修改文件                                         |
| DELETE | /api/files/:id    | 把文件移出清单                                   |
| POST   | /api/scan         | 按启用的规则扫一遍，返回命中清单与汇总           |
| POST   | /api/scan/precheck | 扫前检查，列出刚收录没扫过与上次扫描后改过的文件 |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
