# tp108 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来。文件全靠手工贴进来，收录时会做一次成组校验：路径、后缀、内容逐项查，内容里明显贴错的东西（整段说明文字当成脚本、行数比原文件多得离谱）也会当场拦下，几处问题一次全部列出。扫描之前还可以先过一道只读的检查，看清这一轮范围里哪些文件刚收录还没扫过、哪些在上次扫描后改过内容。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5108>

端口固定为 `5108`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除
2. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单。保存时做整组校验，几处问题会一次全部列出并标到对应的输入项上
3. 命中清单区顶部可以选定只看某一条规则、某一个文件或者某一个级别；点扫描前检查，页面上列出这一轮范围里刚收录还没扫过的文件、上次扫描后内容有改动的文件，各有几个、都是谁，并提示这一轮的命中与上一轮是否可比——检查只提示不改数据，点多少次结论都一样；点按规则扫一遍，页面上给出这一轮参与比对的规则条数、范围里的文件个数、一共命中多少条，并按级别、按规则、按文件分别汇总
4. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；如果指定了一条停用的规则，页面上会写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符
- 收录与修改文件时按整组校验：路径、后缀、内容、备注逐项查，几处问题一次报完
- js、sh 文件的内容里如果大段都是说明文字，按贴错了处理，保存时拦下
- 修改文件时新内容行数比原文件多出太多（翻到三倍开外且多出 20 行以上），按贴错了处理，保存时拦下

## 扫描前检查口径

- 每扫成一轮，就把扫描时刻记到每个被扫到的文件上；扫描前检查只读这份记录，自己一个字都不写，所以点多少次结论都一样
- 范围里没有扫描记录的文件算「刚收录还没扫过」，内容改动时刻晚于最近一次被扫时刻的算「上次扫描后内容有改动」；内容的改动时刻只在路径或内容真的变了的时候才更新，单改备注不算
- 两类里有任何一类不空，就提示这一轮的命中与上一轮不可比；还没有扫过任何一轮时，提示这是第一轮

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...], "meta": {...} }`。文件记录里除了路径、内容、备注，还有内容改动时刻 `contentUpdatedAt`；`meta` 里是扫描记录（最近一轮扫描时刻、每个文件最近一次被扫到的时刻），只由扫描动作维护。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径              | 说明                                             |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | /api/health       | 服务状态检查                                     |
| GET    | /api/rules        | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索 |
| POST   | /api/rules        | 新建规则                                         |
| GET    | /api/rules/:id    | 查看单条规则                                     |
| PATCH  | /api/rules/:id    | 修改规则                                         |
| DELETE | /api/rules/:id    | 删除规则                                         |
| GET    | /api/files        | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files        | 收录文件（整组校验，几处问题一次报完）           |
| GET    | /api/files/:id    | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id    | 修改文件                                         |
| DELETE | /api/files/:id    | 把文件移出清单                                   |
| GET    | /api/scan/precheck | 扫描前检查：刚收录未扫与扫后改过的文件清单，只读 |
| POST   | /api/scan         | 按启用的规则扫一遍，返回命中清单与汇总           |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上；成组校验没过关时会再带上 `problems` 清单，逐项给出错误码、说明与出错位置。
